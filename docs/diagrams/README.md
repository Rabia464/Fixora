# Fixora UML diagrams (SRS)

UML diagrams for the Software Requirements Specification, drawn from the code on `main`
(`frontend/src/lib/domain`, `lib/server`, `lib/ai`, `app/api/v1`) and the Scope Document v1.0
feature IDs (F1 to F10). There are two editable forms of every diagram.

## 1. Live links (open in any browser, no login)

Each **Edit live** link opens the diagram in the PlantUML web editor. The whole diagram is encoded in
the link, so it always opens exactly this version; edit the text on the left and the picture updates.
After editing, copy the new URL from the page (or paste the text back into `src/`) to keep the change.

## 2. StarUML project

[`Fixora.mdj`](Fixora.mdj) holds the same model and all 12 diagrams as native StarUML diagrams
(open it with **File > Open** in StarUML). StarUML is a desktop app and has no hosted share links,
which is why the live links above use PlantUML. Model explorer layout:

| Model | Diagrams |
|---|---|
| Use Case Model | Use Case Diagram |
| Design Model | Class Diagram; Complaint State Machine (under `Complaint`) |
| Data Model (ERD) | ERD (Firestore collections) |
| Component Model | Component Diagram |
| Deployment Model | Deployment Diagram |
| Interactions | 5 sequence diagrams (submit, review/forward, maintenance, confirm/reopen, sign in) |
| Activities | Activity: complaint handling (swimlanes) |

The `.mdj` file is generated, so its layout is a starting point: drag boxes to tidy them, then save.
`alt`/`opt` branches in the sequence diagrams appear as `[guard]` prefixes on the messages.

## Updating

- Edit the `.puml` file in `src/`, then regenerate images with the PlantUML jar:
  `java -jar plantuml.jar -tpng -o ../png src/*.puml` (and `-tsvg -o ../svg`).
- Regenerate a live link by pasting the file into https://www.plantuml.com/plantuml/ and copying the URL.
- Keep the state machine in step with `TRANSITIONS` in `frontend/src/lib/server/workflow.ts`.
